# 手动上下文压缩（第一阶段）

用户明确要求“压缩当前上下文”时，模型可调用无参数异步工具
`compressConversationContext`。本阶段不自动触发，不调用总结分享工具。

## 历史与请求分离

- ContextManager.getHistory 仍是界面和归档来源。
- getRequestMessages 构造深拷贝，用“旧摘要 + 未覆盖原文”生成请求，再做工具配对整理。
- 摘要是 assistant 历史资料，不作为 system 指令；应用的系统提示词继续单独加入。
- 原始历史不因摘要或超限缩短而截断；原先启动时自动清理历史、请求规范化写回、
  追加时按 maxRounds 截断的路径已停用。用户主动删除/清空仍保留。
- 超限回退只减少请求副本中的完整用户轮次，不写回历史。仅剩一轮还超限时停止重试。

## 摘要提交

保留最近两轮用户对话，较早部分必须在完整工具批次边界结束。
生成开始时复制当前模型名称、URL、端点和认证信息，后台发送一次不带工具的摘要请求。
切换模型不会改变这次请求。摘要属于发起工具的原会话，切换后沿用旧工具链不自动续接的机制。
同会话只允许一个压缩任务。摘要成功后普通工具流程可继续使用新的请求上下文。

单独存储摘要、覆盖消息数、原文前缀 SHA-256 指纹、模型、时间和可用的 usage；
usage 保存在摘要记录中，本阶段不计入主聊天回复的用量汇总。
提交时重新验证前缀；并发编辑、删除导致指纹不符时不应用。
之后若原文被修改，投影回退到完整原文，不使用陈旧摘要。
仅用量元数据变化不影响指纹；对象键排序规范化避免序列化顺序造成误判。

SQLite v1→v2 只新增 request_context 表，保留 messages/sessions 及原始行；
老库已有超大消息的分块读取仍保留。摘要保存失败会抛错，不会假报成功。
不支持在非 SQLite 存储中悄悄丢弃摘要（默认保存接口明确报错）。

## 第一阶段边界

已取消 120000 字符的总长度拒绝。资料按用户轮次/工具批次组合，每段最多约 48000 字符；
超过单段的巨大轮次或消息按原顺序拆分，不截断字符或拆开 UTF-16 代理对。
每次请求包含此前累计摘要和本段资料，生成新的累计摘要；最终一次成功后才提交。
覆盖范围仍按原始完整对话/工具批次确定，临时资料分片不是独立工具调用。
结果中的 summaryRequests 表示模型请求次数，sourceCharacters 表示分段资料字符总数；
用量按模型返回的 token 计数跨请求累计。任何一段失败都不保存部分摘要。
长历史需要更多请求、时间及用量；单段字符预算不等于模型 token 上限；
每段最多请求 3 次（首次加最多 2 次恢复）：空摘要重试，超长摘要作为资料请求进一步精简。
精简后仍不合格会明确报告段号、空/过长原因和长度，不提交部分结果；网络/协议异常不盲目重试。
summaryRequests 包含恢复请求。恢复也会增加模型用量和耗时。
诊断日志标记为 [CONTEXT_COMPRESSION]，含操作标识、段号、尝试次数、模式、字符数、
耗时、HTTP 状态及受限的完成原因；不记录正文、摘要、认证信息或服务端原始响应。
工具成功和失败回复均包含 timings：totalMs 为本次总耗时，stages 为各阶段耗时，
包括界面排队、快照、后台排队、分段准备、摘要、验证、保存排队和保存（仅列经过的阶段）。
requests 逐次列出 segment、attempt、elapsedMs、输入/输出字符数及结果；
摘要阶段耗时包含这些请求，不能把 stages 和 requests 相加。失败时也保留已发生的统计。
这些统计用于观察性能，不代表摘要质量或已经提供可调压缩程度参数。
多模态原文仍保存，但此版摘要器只接收文本化资料，不能解释图像内容。
空摘要、非正常完成、工具调用响应、摘要过长/未缩短、HTTP/解析失败均不提交。
这不是模型 token 预算估算：来源未超过本地阈值也可能被接入点拒绝，原状态仍保留。
自动触发、精确预算估算及接入点超限后的自适应重分段留待后续。

## 验证

JVM 测试覆盖请求副本隔离、摘要失效回退、完整工具批次边界、用量变化、键顺序。
Android 测试覆盖 v1 升级保留原行、摘要恢复与会话隔离、24 条历史在压缩和请求缩短后不变。
本地 Java 编译及 JVM 测试通过；Android 测试仅编译，尚未设备执行。
未对真实模型发出收费测试请求。正式 APK、实际模型兼容性及 A→B→A 慢摘要回调须真机验收。
